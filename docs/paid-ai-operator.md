# Paid-AI operator commands

Generate, Transcribe, and Review now require a valid browser session and central Redis admission before any paid provider is constructed. Public deployment still requires the separate Vercel/Redis/HTTPS acceptance gate.

Use Node 22.13+ with server-only environment variables from a secure operator environment. `.env.example` lists names and defaults; never commit actual values or place them in command arguments. Provide a managed Upstash-compatible REST URL and standard write token, two independent 32-byte hex HMAC secrets, and a base namespace. Vercel production and preview use distinct key suffixes; use distinct Redis databases as an additional operational safeguard. The switch is absent by default and therefore fails closed. Set `ARCHITEKT_PAID_AI_ALLOWED_ORIGINS` to the exact HTTPS production origin. Development localhost and 127.0.0.1 origins must each be listed explicitly when needed. Preview AI stays unavailable without its own exact origin and separately configured Redis environment. Invite exchange and all three paid routes reject missing, opaque, or cross-site Origins. Do not put secrets or policy under `NEXT_PUBLIC_`.

Run `npm run paid-ai:operator -- enable` to enable admissions after configuration, or `disable` to block new admissions immediately. `status switch` reports only enabled/disabled. `issue-invite` prints a one-time invite code and its non-secret ID; deliver the code privately. It cannot be retrieved later. `status invite <id>` and `status grant <id>` return state and safe timestamps (plus used units for a grant). `revoke invite <id>` blocks an unredeemed invite. Once redeemed, `revoke grant <id>` blocks its session and future admissions. Revoking an already consumed invite alone does not revoke the grant. The invite and grant share the same random ID; the plaintext credential is never stored in Redis.

For a production namespace, prefix **every** command with `--confirm-production`, for example `npm run paid-ai:operator -- --confirm-production status switch`. An expiring local/preview test namespace should be used first. The CLI requires `VERCEL=1` and `VERCEL_ENV=production` to select production; without those it selects development. Never copy production secrets into a preview environment. The operator command emits no document content or raw Redis errors.

The five-second bounded invite body, Redis deadlines, and 120-second reservation TTL are protective limits, not billing guarantees. Operational units are admission weights: generate 2, transcription 1, review 8; defaults are 24 per grant and 120 per UTC day globally. This does not cap exact OpenAI charges. Use a dedicated provider project with spending limits and alerts. A known completed provider operation releases its concurrency slot; ambiguous cancellation or transport failure retains the slot until TTL expiry. Charged units are not refunded after provider execution starts.

The isolated Redis integration suite runs with `ARCHITEKT_TEST_REDIS_REST_URL` and `ARCHITEKT_TEST_REDIS_REST_TOKEN` pointing to a disposable test database: `npx vitest run src/server/paid-ai/paid-ai-redis.integration.test.ts`. It never needs real invite, document, or provider data. The unit suite skips this file when test Redis is unconfigured. It was exercised against an expiring Upstash scratch instance during Slice 2. CI runs the same atomic suite when those two isolated test secrets are configured; otherwise it reports the skip without weakening production behavior.
