# Portable Architecture Documents acceptance — 2026-10-04

Scope: Slice 2C closeout of V5 JSON import/export, deterministic Markdown export, and complete-diagram PNG export. These checks launched the **installed Windows desktop browser binaries** in isolated Playwright sessions, saved the actual browser downloads to disk, parsed the files, and visually inspected representative PNGs. Chrome and Edge were the primary targets; Brave supplied additional Chromium evidence. This is a local acceptance result, not a performance guarantee or a certification of other platforms.

The shared URL-shortener document had eight components across client, gateway, service, cache, queue, and database kinds; eight directed relationships including a reciprocal pair; two populated boundaries and one empty boundary; nontrivial positions; and committed Design Brief prose. Each browser downloaded non-empty `.architekt.json`, `.md`, and `.png` files with the expected `url-shortener-portfolio` stem. Repeating each export worked. PNG file headers and dimensions were valid, and visual inspection showed all eight components, kind labels, populated boundary headers, directed edges, reciprocal arrows, and connection labels. The blank boundary correctly had no canvas rectangle. Browser-specific raster bytes differed slightly in Brave; content remained usable. The portfolio PNG in `docs/screenshots/portable-diagram.png` is the actual Chrome export.

The downloaded JSON was a valid V5 document. Importing that downloaded file over a different document restored DesignContext, all components and kinds, connections and kinds, boundaries and memberships, and positions in each browser. One Undo restored the prior document; one Redo restored the imported document. Markdown had the title, counts, four Design Brief/overview sections, kinds, populated and empty boundaries, and separate reciprocal connection lines. Literal Markdown and HTML-looking prose was escaped; paragraph and explicit line breaks and Unicode remained readable. The artifact contained no coordinates, renderer metadata, AI proposal or Voice state, timestamps, or invented prose. JSON and Markdown downloads were deterministic on repeat.

The same diagram exported from light and dark editor themes with the stable-light palette for nodes, text, boundaries, edges, labels, and arrowheads. Altering the live viewport transform materially changed pan and zoom but left the PNG bytes and dimensions unchanged within each browser; export did not call a visible Fit view or change the live transform. The diagram exceeded the visible viewport and was still complete. Visual inspection found no drafting grid, handles, selection/focus decoration, pending-connection state, Workbench controls, Design Brief, AI, or Voice UI. A separate long-label/Unicode diagram remained legible. A widely spaced two-component diagram exported at 8192 × 184 with both ends included and a resolution-reduction notice rather than cropping.

The 100-component/200-connection fixture used a 10 × 10 grid, two directed relationships per component, and a populated boundary. All browser downloads completed; output was 5268 × 3184, within 8192 pixels per side and 16,777,216 pixels total. The resolution-reduction notice appeared in each browser. Native-resolution inspection showed all nodes and labels; a reduced preview naturally makes dense edge labels harder to read. The exact source-scene bounds were not captured. Each browser remained responsive, had no staging scene after completion, and completed another PNG export. The observed ~9-second runs do not establish a future latency guarantee.

At 390px, JSON, Markdown, PNG, and Import JSON were reachable; a full PNG still exported. Chrome was checked in light and Edge in dark presentation, with no page-level horizontal overflow. A wide-case resolution notice also fit at 390px. The completely empty document, context-only document, and document with only an empty boundary allowed JSON/Markdown but disabled PNG with “Add a component to export a diagram.” A component enabled all three exports. Dirty Design Brief, active boundary drag, and inline rename disabled all three actions; the production browser suite also covers active node drag. Forced PNG download failure announced a safe error, removed staging, restored focus, left the document unchanged, and allowed PNG/JSON/Markdown afterward. Repeated success left no staging tree. Keyboard Enter operated each export; import keyboard operation and focus behavior are covered by the production browser suite. Status, error, disabled guidance, and inert/`aria-hidden` staging were checked in browser DOM. **Actual screen-reader speech was not manually verified.**

Exports left local V5 content, selection, viewport, and history unchanged in the representative runs; no Undo entry was created. An Edge run with a pending Redo showed that all three successful exports and a forced PNG failure preserved the Redo stack, selection, viewport, and stored V5 content. Source inspection found no export call to OpenAI or another provider and no document-content logging; browser request observation found no off-origin export requests. JSON and Markdown serialize/download locally; PNG captures and downloads locally. Voice audio/transcript drafts and transient AI review are excluded. `html-to-image` remains pinned to `1.11.11`; production dependency audit reported zero vulnerabilities. The 2× preferred output policy, proportional reduction, and fixed raster limits remain unchanged.

Limitations: Safari, Firefox, macOS, mobile-device browsers, and actual screen-reader speech were not manually verified. Dense 100/200 graphs are complete but naturally less readable at whole-image preview scale. PNG is export-only, requires at least one component, and may reduce resolution instead of cropping. JSON is the canonical machine-readable portable format; Markdown and PNG are derived human-facing artifacts. No application-code change was required for this acceptance.
