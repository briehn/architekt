# Voice-to-Architecture v1: live acceptance

Date: 2026-10-03. This record separates microphone/transcription observations from architecture-generation observations. The fixed English scripts below are spoken twice each. Audio is not stored in the repository; raw and edited transcript text may be recorded here only for evaluation.

## Fixed scripts

Read each script naturally and use the same wording for both runs of that script. Pause briefly between sentences.

1. **Simple CRUD:** “I need a small app where a browser client calls an API service to create, read, update, and delete records. The service stores those records in PostgreSQL.”
2. **URL shortener:** “Design a URL shortener. A client calls an API to create short links and follow redirects. Keep popular mappings in a cache backed by a database. Send click events asynchronously for analytics so redirects do not wait for reporting.”
3. **Chat:** “Design real-time chat. Clients keep a WebSocket connection to a chat service. The service stores messages and delivers new messages to connected recipients. Tell me how a client can recover messages missed while offline.”
4. **Background processing:** “An API accepts an image-processing job, puts it on a queue, and returns before processing finishes. A worker consumes jobs, transforms the image, and writes the result to object storage.”
5. **Natural correction:** “The API service saves customer records. We use Postgres—actually, make that DynamoDB. A browser client sends requests to the API, and the API reads and writes the customer records.”
6. **Technical vocabulary:** “Put a CDN in front of an API gateway. Clients use WebSocket connections for live updates. The service uses Redis for fast lookups, PostgreSQL for durable records, Kafka for asynchronous events, and object storage for uploaded files.”

## Evaluation method and preflight

- Target: English dictation on Windows desktop Chrome and Edge with a physical microphone. Brave is recorded as additional Chromium compatibility evidence. The real app's `Speak → record → transcribe → review/edit transcript → Generate → proposal review → Apply` path is required for completion.
- Server-side `OPENAI_API_KEY` is configured; its value was not inspected or logged. No model override was found. The configured transcription model is `gpt-transcribe`; generation defaults to `gpt-6-luna` with medium reasoning.
- At the first device check, Edge exposed an audio-input candidate but `getUserMedia` returned `NotAllowedError`. Chrome was not found in the usual installation paths. These are environment observations, not a claim that either browser is unsupported. The user later found that Windows had selected the wrong microphone and switched input devices. The Codex in-app browser then captured intelligible speech; that browser is not a substitute for the Chrome/Edge support-target checks.
- The [official OpenAI model page](https://developers.openai.com/api/docs/models/gpt-transcribe) lists **$0.0045 per audio minute** on this date. Any cost figure below will estimate only the measured submitted audio duration; account-specific billing may differ.
- Ten browser voice cases and the prior synthetic-media suite provide deterministic coverage for bounds, stale callbacks, retry, failure copy, and responsive behavior. They do not count as real-microphone quality samples.
